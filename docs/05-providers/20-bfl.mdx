# Black Forest Labs Provider

Black Forest Labs (founded by Stable Diffusion creators) provides FLUX models - the next generation of image synthesis with exceptional quality and prompt adherence.

## Setup

### Installation

```go
import (
    "github.com/digitallysavvy/go-ai/pkg/ai"
    "github.com/digitallysavvy/go-ai/pkg/providers/bfl"
)
```

### Configuration

```go
provider := bfl.New(bfl.Config{
    APIKey: os.Getenv("BFL_API_KEY"),
})

model, err := provider.ImageModel("flux-pro-1.1")
```

### Get API Key

```bash
export BFL_API_KEY=...
```

## Provider-Specific Features

### Exceptional Quality

FLUX models produce photorealistic and artistically sophisticated images:

```go
result, err := ai.GenerateImage(ctx, ai.GenerateImageOptions{
    Model:  model,
    Prompt: "A photorealistic portrait of an elderly person with expressive eyes",
    Size:   "1024x1024",
})
```

### Perfect Text Rendering

FLUX excels at text in images:

```go
result, err := ai.GenerateImage(ctx, ai.GenerateImageOptions{
    Model:  model,
    Prompt: "A storefront sign that says 'Coffee & Code' in elegant typography",
})
```

### Advanced Prompt Understanding

Complex, nuanced prompts work well:

```go
result, err := ai.GenerateImage(ctx, ai.GenerateImageOptions{
    Model: model,
    Prompt: "A cyberpunk street scene at night, neon reflections on wet pavement, " +
        "shallow depth of field, cinematic composition, blade runner aesthetic",
})
```

### FLUX 3 Image

`flux-3-image` supports text-to-image and reference-image editing (up to 10
images passed through `Files`). It does not accept masks, `Seed`, or the legacy
`width`/`height`, `steps`, `guidance`, `outputFormat`, `promptUpsampling`, `raw`,
`imagePrompt*`, `inputImage*`, and webhook provider options; those produce
`unsupported` warnings.

Provider options (`providerOptions["blackForestLabs"]`): `resolution`
(`768sq`, `1k`, `1.5k`, `2k`, `4k`), `grounding` (bool), `version` (`latest`),
`safetyTolerance` (integer 0-7), `pollIntervalMillis`, and `pollTimeoutMillis`.

Accepted aspect ratios are `21:9`, `2:1`, `16:9`, `3:2`, `7:5`, `4:3`, `5:4`,
`1:1`, `4:5`, `3:4`, `5:7`, `2:3`, `9:16`, `1:2`, and `9:21`. A ratio derived from
`Size` (such as `7:3`) is normalized to an accepted one where possible; an
unsupported ratio is omitted with a warning so the endpoint chooses automatically.

```go
model, _ := bflProvider.ImageModel("flux-3-image")

result, err := model.DoGenerate(ctx, &provider.ImageGenerateOptions{
    Prompt:      "a studio photo of a ceramic teapot",
    AspectRatio: "16:9",
    ProviderOptions: map[string]interface{}{
        "blackForestLabs": map[string]interface{}{
            "resolution":      "2k",
            "safetyTolerance": 2,
        },
    },
})
```

#### FLUX 3 Image Klein

Unknown image model IDs use the latest supported image API, currently FLUX 3
Image Klein's request format and options (`flux-pro*`, `flux-dev`,
`flux-kontext-*`, `flux-1*` and `flux-2*` keep the legacy format, and
`flux-3-image` keeps its own grounding and version controls). Klein uses the
same `resolution`, `AspectRatio` and `Files` inputs as `flux-3-image` (reference
images are sent in the `images` array), and also accepts `Seed`, `outputFormat`
(`jpeg` or `png`) and `steps` (1-16).

For exact dimensions pass `Size` (for example `2048x2048`) or both
`width` and `height` provider options. Each dimension must be an integer from 64
to 6256 and the product must not exceed 16,822,272 pixels. Provider dimensions
override `Size`; exact dimensions override `resolution` and `AspectRatio`.
Klein does not accept masks, `grounding`, `version`, `guidance` or `inputImage`
(these produce `unsupported` warnings; masks are rejected).

```go
model, _ := bflProvider.ImageModel("flux-3-image-klein")

seed := 42
result, err := model.DoGenerate(ctx, &provider.ImageGenerateOptions{
    Prompt:      "Change the sky to sunset while preserving the buildings",
    AspectRatio: "16:9",
    Seed:        &seed,
    Files:       []provider.ImageFile{{Type: "url", URL: "https://example.com/village.png"}},
    ProviderOptions: map[string]interface{}{
        "blackForestLabs": map[string]interface{}{
            "resolution":   "2k",
            "outputFormat": "png",
            "steps":        16,
        },
    },
})
```

Polling continues through the `Reasoning` and `Generating` statuses and stops
with `Black Forest Labs generation failed: <status>.` for `Request Moderated`,
`Content Moderated`, and `Task not found`. Signed image downloads from BFL
delivery hosts are sent without API credentials; a custom proxy base URL still
receives the provider and request headers on same-origin downloads.

## Examples

### Basic Image Generation

```go
package main

import (
    "context"
    "fmt"
    "log"
    "os"

    "github.com/digitallysavvy/go-ai/pkg/ai"
    "github.com/digitallysavvy/go-ai/pkg/providers/bfl"
)

func main() {
    provider := bfl.New(bfl.Config{
        APIKey: os.Getenv("BFL_API_KEY"),
    })

    model, err := provider.ImageModel("flux-pro-1.1")
    if err != nil {
        log.Fatal(err)
    }

    result, err := ai.GenerateImage(context.Background(), ai.GenerateImageOptions{
        Model:  model,
        Prompt: "A majestic dragon perched on a mountain peak at sunrise",
        Size:   "1024x1024",
    })
    if err != nil {
        log.Fatal(err)
    }

    os.WriteFile("dragon.png", result.Images[0].Data, 0644)
    fmt.Println("Image saved to dragon.png")
}
```

### Professional Photography

```go
result, err := ai.GenerateImage(ctx, ai.GenerateImageOptions{
    Model: model,

        "soft studio lighting, shallow depth of field, 85mm lens, f/1.4",
```

### Fill Models

`flux-pro-1.0-fill` uses Black Forest Labs' fill request format. Pass the source image through `Files`; the provider maps it to the `image` request field required by the upstream API.

```go
model, _ := bflProvider.ImageModel("flux-pro-1.0-fill")

result, err := model.DoGenerate(ctx, &provider.ImageGenerateOptions{
    Prompt: "replace the background with a studio wall",
    Files: []provider.ImageFile{{
        Data:      imageBytes,
        MediaType: "image/png",
    }},
})
```

### Artistic Styles

```go
styles := []string{
    "oil painting, impressionist style",
    "watercolor, loose brushstrokes",
    "digital art, concept art style",
    "pencil sketch, detailed cross-hatching",
}

basePrompt := "A serene forest path"

for i, style := range styles {
    prompt := fmt.Sprintf("%s, %s", basePrompt, style)
    result, err := ai.GenerateImage(ctx, ai.GenerateImageOptions{
        Model:  model,
        Prompt: prompt,
    })
    if err != nil {
        continue
    }

    filename := fmt.Sprintf("forest_%d.png", i)
    os.WriteFile(filename, result.Images[0].Data, 0644)
}
```

## Video Generation (FLUX 3)

`provider.VideoModel(modelID)` (e.g. `"flux-video"`) generates a single
video per call (`MaxVideosPerCall() == 1`) — FLUX 3 video does not accept a
custom frame rate or seed:

```go
videoModel, err := provider.VideoModel("flux-video")
if err != nil {
    log.Fatal(err)
}

result, err := ai.GenerateVideo(ctx, ai.GenerateVideoOptions{
    Model:  videoModel,
    Prompt: ai.VideoPrompt{Text: "A time-lapse of clouds over a mountain range"},
})
if err != nil {
    log.Fatal(err)
}

for _, video := range result.Videos {
    fmt.Println(video.URL)
}
```

`VideoModel` also implements `provider.VideoModelStarter` /
`VideoModelStatusChecker`, so it works with `ai.ExperimentalStartVideo` /
`ai.ExperimentalGetVideoStatus`.

## Best Practices

1. **Prompt Engineering**
   - Be detailed and specific
   - Include style, mood, lighting
   - Mention technical details (lens, lighting, etc)
   - FLUX understands complex descriptions

2. **Model Selection**
   - Use flux-pro-1.1 for final production
   - Use flux-dev for development/testing
   - Use flux-schnell for rapid prototyping

3. **Quality Optimization**
   - FLUX needs fewer iterations than SD
   - Prompts can be more natural/conversational
   - Text in images works reliably

4. **Cost Management**
   - Use schnell for experimentation
   - Switch to pro for finals
   - Batch similar requests
