# Harness adapters

An adapter wraps one coding-agent runtime. It implements `harness.Harness` and returns a `harness.Session`. `harness.Agent` is the only consumer of that interface, so a test double is a first-class substitute for a real adapter. Application code usually builds an adapter with its constructor and hands it to `harness.NewAgent`. See [Harness agent](./agent.mdx).

## Harness

```go
type Harness interface {
	SpecificationVersion() string // always "harness-v1"
	HarnessID() string
	BuiltinTools() map[string]BuiltinTool
	DoStart(ctx context.Context, opts StartOptions) (Session, error)
}
```

`harness.SpecificationVersion` is the version string. `BuiltinTools` is keyed by what the runtime reports on tool-call events: the common name when it has one, otherwise the native name.

Optional capabilities are separate interfaces that an adapter may also implement:

| Interface | Purpose |
| --- | --- |
| `harness.BootstrapProvider` | Declare a [bootstrap recipe](./sandbox.mdx#bootstrap-recipes). |
| `harness.BuiltinToolApprovalSupport` | Emit approval requests for built-in tools. |
| `harness.BuiltinToolFilteringSupport` | Hide inactive built-in tools from the runtime. |
| `harness.LifecycleStateValidator` | Validate the adapter-defined `data` in lifecycle state. |

## Session

```go
type Session interface {
	SessionID() string
	IsResume() bool
	DoPromptTurn(ctx context.Context, opts PromptTurnOptions) (PromptControl, error)
	DoCompact(ctx context.Context, customInstructions string) error
	DoContinueTurn(ctx context.Context, opts ContinueTurnOptions) (PromptControl, error)
	DoSuspendTurn(ctx context.Context) (*ContinueTurnState, error)
	DoDetach(ctx context.Context) (*ResumeSessionState, error)
	DoStop(ctx context.Context) (*ResumeSessionState, error)
	DoDestroy(ctx context.Context) error
}
```

An adapter whose runtime cannot compact returns `*harness.CapabilityUnsupportedError` from `DoCompact`. A session may also implement `harness.HistoryReader` (`DoReadHistory(ctx, since string) (*ReadHistoryResult, error)`). `since` is a previous result's cursor, which is opaque to the host. An adapter that cannot reach its runtime's store returns `*harness.HistoryUnavailableError`.

## PromptControl

`DoPromptTurn` and `DoContinueTurn` return a `harness.PromptControl`, the control surface for the turn.

```go
type PromptControl interface {
	SubmitToolResult(ctx context.Context, result ToolResultSubmission) error
	Done() <-chan struct{} // closed when the turn ends
	Err() error            // the turn error, after Done is closed
}
```

{/* gen:fields harness.ToolResultSubmission */}

| Field | Type | Description |
| --- | --- | --- |
| `ToolCallID` | `string` |  |
| `Output` | `any` |  |
| `IsError` | `bool` |  |
| `ToolResult` | `any` | ToolResult optionally carries the full tool-result part (TS `ToolResultPart`) for adapters that forward it verbatim. |

{/* /gen:fields */}

When a host tool defines `types.Tool.ToModelOutput`, the host runs it once per submitted result and sets `ToolResult` to a `*harness.ModelToolResult`. Its `Output` is the model-facing representation, limited to text and inline images. The adapter should build the runtime's tool response from it, using `harness.ConvertToolModelOutput`, while `Output` stays the raw result for consumer-facing events. The raw result is kept on the tool result, and `ResponseMessages` reports the model output. Adapters that cannot deliver images should return a `*harness.CapabilityUnsupportedError` or omit them with a diagnostic.

A control can also implement:

| Interface | Method |
| --- | --- |
| `harness.ToolApprovalSubmitter` | `SubmitToolApproval(ctx, ToolApprovalSubmission) error` |
| `harness.UserMessageSubmitter` | Accepts a user message mid-turn, which is what `ExperimentalSteer` uses. |
| `harness.CheckpointPinner` | `PinCheckpoint() (release func())`. Pins the replay checkpoint so already-delivered bridge events are kept until you call `release`. |

## Built-in adapters

### Image input

User messages can carry inline images next to text. `harnessutil.ExtractPromptContent` normalizes a `harness.Prompt` into plain text (a bare string, or a message whose parts are all text, joined with a blank line) or into ordered text and base64 image parts. Claude Code, Codex, OpenCode, Deep Agents and the ACP-based adapters use it.

Pass an image as an `types.ImageContent`, or as a `types.FileContent` whose media type starts with `image`. The data can be bytes, a base64 string, or a base64 `data:` URL. When the media type is only `image` or `image/*`, it is taken from the `data:` URL or detected from the bytes.

The helper rejects these inputs with a `*harness.CapabilityUnsupportedError`, before any turn starts:

- remote image URLs
- provider file references
- `data:` URLs that are not base64 encoded
- images whose media type cannot be detected
- files that are not images
- content parts other than text, image and file

```go
msg := types.Message{
	Role: types.RoleUser,
	Content: []types.ContentPart{
		types.TextContent{Text: "What is in this image?"},
		types.FileContent{MediaType: "image/png", Data: pngBytes},
	},
}
result, err := agent.ExecuteWithMessages(ctx, []types.Message{msg})
```

See `examples/harness/image-input` for a runnable program.

### Adapter notes

- **ACP single bridge manifest.** The separate `implementation/` install layer is gone. A `SourceNPMLocked` source is the complete bridge installation: its `package.json` and lockfile replace the bridge's own, so they must also declare every dependency of the ACP bridge manifest at the same version. A `SourceInstallCommand` source installs the bridge's own manifest, then runs the command through `install.sh` with `HOME` set to `<bootstrap dir>/home`. The agent starts from the launch command the host passes to the bridge, and the `--implementation-dir` bridge argument no longer exists. `SourceNPMSimple` is deprecated because TS removed it. It still works as a shim for an install command that runs `npm install --global --prefix "$HOME/.local" <package>@<version>` in the private home.
- **ACP saved sessions from earlier builds do not resume.** The lifecycle state key is now `agentIdentity` (it was `implementationIdentity`), the identity digest covers a different payload, and the persisted `providerKind` no longer accepts `implementation-default`. TS invalidates every earlier ACP session the same way. An affected session is rejected when the agent validates the saved state, with "Lifecycle state failed schema validation for harness '<id>': ACP lifecycle state data: agentIdentity must be a string." (the TS zod failure for the missing `agentIdentity` key). State that carries `agentIdentity` but was written for a different agent configuration fails with "ACP lifecycle state is incompatible with the configured agent." Start a new session. Sandboxes bootstrapped by an earlier build also keep the old `implementation/` directory, which the new bridge does not use. This applies to the Cursor, GitHub Copilot, Grok Build and fx adapters.
- **Bridge connection.** Bridge-backed adapters (Claude Code, Codex, Deep Agents, OpenCode and the ACP adapters) share `bridge.NewBridgeConnectFunc`. A connection counts as established only after the bridge sends `bridge-hello`. The initial open retries for the startup timeout and is cancelled by the context of the start call. A reconnect makes a single attempt, because the channel retries it itself. `bridge.ConnectReasonFromContext` tells a connect function which of the two it is serving. Basic sandbox sessions need `Port` and `PortEndpoint`, and `MintBridgeToken` needs a sandbox id. The errors use the harness-neutral TS wording, for example "The harness requires an explicit `port` setting when using a basic sandbox session." Unlike TS, a bridge that rejects the connection as unauthorized (close code 1008) is retried until the startup timeout, because the Go WebSocket client does not expose close codes.
- **Resolved model.** Every adapter reports the model it ran with in the `stream-start` part's `modelId`, also when the prompt sets no model. The ACP bridge reads it from the session state, so the start frame now always carries the model mapping. Codex uses the model from its thread response. Claude Code ignores its `command_lifecycle` frames when it picks the model. GitHub Copilot in AI Gateway mode exposes no model over ACP, so `stream-start` parts without one report `githubcopilot.GatewayModel` through `acp.Settings.StreamStartFallbackModelID`.
- **ACP image prompts.** User messages with inline images reach the agent as ACP image content blocks. The bridge rejects an image prompt with a `*harness.CapabilityUnsupportedError` when the agent does not advertise `promptCapabilities.image` and `NonTextContentTypes` does not declare `image`. `acp.TextContentBlock` is now an alias of `acp.ContentBlock`, which has the new image fields.
- **ACP image tool output.** `acp.Settings.NonTextContentTypes` declares the non-text tool model output the runtime can deliver to its model. Text is always supported. The only value is `acp.NonTextContentImage`, which the Cursor, GitHub Copilot and Grok Build adapters set. GitHub Copilot only processes tool output images with direct GitHub authentication; with AI Gateway the CLI passes only the text. It also enables image prompts when the ACP agent does not advertise image prompt support. For a runtime that does not declare it, image content from a tool's `toModelOutput` transformation is omitted and the bridge writes a warning to stderr. The fx adapter does not declare it, so it receives text only.
- **ACP `pnpmWorkspaceYaml`.** In `acp.Source`, an empty `PnpmWorkspaceYAML` means unset. TS rejects an explicitly empty `pnpmWorkspaceYaml`; Go treats it the same as omitting the field.
- **Client attribution.** Adapters send their identity as `<name>/<version>` in the `User-Agent` and `x-client-app` headers. The name is `ai-sdk-harness-<id>` (for example `ai-sdk-harness-claude-code/1.0.155`) with a single `/`, as RFC 9110 requires. Earlier builds sent `ai-sdk/harness-<id>/<version>`. The ACP agent identity includes the client app, so a change to it invalidates saved ACP session state.
- **ACP AI Gateway profile.** When `CredentialBrokering` or `CredentialForwarding` is configured and the provider authentication resolves to AI Gateway, the host resolves the `ProviderAuthentication.GatewayEnv` profile itself. It places the resolved variables (credentials replaced by sandbox placeholders when brokered) in the bridge process environment and tells the bridge `providerEnvironment` is empty. Without either option, the bridge resolves the profile from `AI_SDK_ACP_GATEWAY_*` at startup.
- **ACP cancellation.** Cancelling the context of an ACP prompt sends `abort` to the bridge and the turn settles with the cancellation error once the bridge reports `finish` (or the connection closes), so the final events are still delivered and the session accepts the next prompt. `context.Cause` of the cancelled context is the error returned.
- **ACP permission mapping.** `acp.PermissionModeMapping` always has all three modes; a nil target is an explicit no-op for that mode (`null` on the wire). TS also accepts a partial mapping, which it ignores outside the implementation identity; set `UnsetAllowReads`, `UnsetAllowEdits` or `UnsetAllowAll` for the left-out modes to get the same behavior (a partial mapping is never sent to the bridge). With no flag set the mapping is complete. The struct stays comparable with `==`.
- **OpenCode built-in tool filtering.** `opencode` supports `BuiltinToolFiltering`. OpenCode controls `write` and `edit` through one permission, so they must be both active or both inactive. `DoStart` returns a `*harness.CapabilityUnsupportedError` otherwise.
- **Claude Code.** The built-in tool catalog includes `ListAgents` (read-only), so it can be listed in `inactiveTools`.
- **Deep Agents and OpenCode.** Ripgrep ships with the bridge as an npm dependency. The Deep Agents bootstrap no longer downloads it with `curl`.
- **fx.** The install command pins a specific fx release (`bash -s -- v<version>`) instead of the latest one. The `terminal` built-in tool was removed; use `shell`. The `skill` tool takes a required `location` and an optional `resource`.
- **fx libfx runtime (preview).** The SDK can host the libfx core, `fx-core.wasm` from the `libfx` npm package (pinned to `fx.LibfxVersion`, 0.0.14), in process on wazero. `fx.Settings{Runtime: fx.RuntimeLibfx}` selects it (see the next item); the default stays the sandbox `fx acp` adapter, `fx.RuntimeSandboxACP`. Nothing is downloaded at import time. `fx.PrepareWasm(ctx, *fx.WasmSource)` resolves the module on demand: `Bytes`, then `Path`, then the cache, then `URL`, then the npm tarball with the jsDelivr single-file mirror as fallback. Downloads go through the SDK's SSRF-safe download client. The tarball must match the npm `sha512` integrity before any entry is read, and every module, whatever its source, must match `fx.LibfxWasmSHA256` unless `AllowUnpinned` is set. The module and a wazero compilation cache live under `os.UserCacheDir()/go-ai/fx/<version>/` (directories `0700`, files `0600`). A corrupt cache entry is deleted and fetched again. The compilation cache holds machine code, so it is kept on disk only when the cache root and version directory are owned by the current user and not group- or world-writable (checked on Unix); otherwise it stays in memory. `GO_AI_FX_WASM_PATH`, `GO_AI_FX_WASM_URL`, `GO_AI_FX_CACHE_DIR` and `GO_AI_FX_OFFLINE=1` fill empty `WasmSource` fields; the path and URL variables apply only when none of `Bytes`, `Path` and `URL` is set. An offline or failed fetch returns `*fx.WasmUnavailableError` (`errors.Is(err, fx.ErrWasmUnavailable)`), whose message names the version, the hash, the cache path and the fixes. A hash mismatch returns `*fx.WasmIntegrityError` (`fx.ErrWasmIntegrity`). Before the module runs, its import table is compared, name for name and signature for signature, with the interface the SDK hosts; a mismatch returns `*fx.WasmInterfaceError` (`fx.ErrWasmInterface`), which lists the added, removed and changed imports. Unlike TS, the core's own HTTP requests may only reach the AI Gateway and the codex and grok subscription origins. To move to a new libfx release, run `go run ./pkg/harness/fx/internal/libfx/genpin -version <version>` (or `LIBFX_VERSION=<version> go generate ./pkg/harness/fx/internal/libfx`). It rewrites the version, URLs, hashes and import table in `pin_gen.go`. Then review the import diff and run `GOAI_FX_WASM_TEST=1 go test ./pkg/harness/fx/...`, which boots the real module.
- **fx libfx runtime sessions.** `fx.CreateFx(fx.Settings{Runtime: fx.RuntimeLibfx})` returns the port of TS `createFx()` from `@ai-sdk/harness-fx`. Each turn starts a fresh core from the session checkpoint, so nothing in the sandbox needs installing and no port is exposed. The built-in tools are `fx.LibfxBuiltinTools`: `read`, `write`, `edit`, `bash`, `grep`, `glob`, `ls` and `askUserQuestions`. They run as commands in the session sandbox, confined to `SessionWorkDir` after symlinks are resolved. The sandbox needs bash, GNU `realpath -m`, `base64 -w0` and `find -printf`, so use a Linux sandbox. `BuiltinToolFiltering` and built-in tool approvals are supported (`bash` needs approval unless the mode is `allow-all`; `write` and `edit` need it under `allow-reads`). Custom tools wait for `SubmitToolResult`. Steering (`SubmitUserMessage`), cancellation through the turn context, `DoSuspendTurn` and cold continuation all work. A continued turn replays the recorded model responses without network requests. It never runs a tool call again that was executing when the turn stopped: such a call gets the error "This tool execution was interrupted and its outcome is unknown." `DoCompact` returns a `*harness.CapabilityUnsupportedError`. The runtime keeps a private state file at `<sandbox HOME>/.ai-sdk-harness/.agent-runs/<session>/fx/state.json` (directory `0700`), written as a temp file and then `mv`, and the file must lie outside `SessionWorkDir`. Its format is byte-compatible with TS. The lifecycle data is `{version: 1, stateFileName}`. Settings that apply only to this runtime are `Headers` (sent on AI Gateway requests), `Effort`, `ServiceTier` (`default`, `fast` or `ultrafast`), `Backend` (`wasm`/`auto`; `native` returns a `*harness.CapabilityUnsupportedError`), `Wasm`, `MemoryLimitBytes` (default 1 GiB per core) and `HTTPClient` (default: SSRF-safe). The core's requests reach only the AI Gateway base URL (`AI_GATEWAY_BASE_URL`; requests for `https://ai-gateway.vercel.sh` are rewritten to it) and libfx's provider origins. Authentication is AI Gateway only (`AI_GATEWAY_API_KEY`, then `VERCEL_OIDC_TOKEN`). The core never holds the credential: it gets a random placeholder, which the host swaps for the real key on AI Gateway requests only. The real key is removed from every response before the core or the state file sees it. Codex and grok subscriptions and `MCPServers` are not supported on this runtime yet; `MCPServers` makes `CreateFx` return a `*harness.CapabilityUnsupportedError`. The sandbox-ACP settings `Port`, `PortEndpoint`, `StartupTimeoutMS`, `Reconnect`, `MintBridgeToken` and `CredentialForwarding` are ignored. Lifecycle state from the other runtime returns `*fx.IncompatibleStateError`, which names the `Runtime` to resume it with. Parts reach `Emit` in order from one goroutine per turn, so an `Emit` callback may call `DoSuspendTurn`, `DoStop`, `DoDetach`, `DoDestroy` or, after the `finish` part, `DoPromptTurn` synchronously. Parts that have not reached `Emit` when the turn starts suspending are dropped, and the continued turn emits them again. The turn waits for its parts to reach `Emit` before it moves on, except for the echo of `SubmitToolResult`, which follows on `Emit` after the call returns with the result saved. `Done()` closes after the last part has been delivered, so an `Emit` callback must not wait on its own turn's `Done()`.

### Authentication

Every adapter takes an `Auth` setting of type `harness.Authentication`. Leave it unset to detect the route, or choose `harness.AuthModeDirect`, `harness.AuthModeAIGateway` or an isolated environment with `harness.AuthEnvironment`. Adapters forward credentials into the sandbox through request transformations where the provider supports it, so the sandbox does not hold the real secret. See [Request transformations](./sandbox.mdx#request-transformations).
