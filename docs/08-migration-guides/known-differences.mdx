# Known differences from the TypeScript AI SDK

The Go AI SDK tracks the TypeScript AI SDK (`ai@7.0.170` as of v0.6.0) closely, but a
few areas are intentionally different, either because the Go runtime has no
equivalent primitive or because a decision was made to diverge. This page is
the reference for both.

## StreamObject is not lazy

`StreamObject` is deprecated in both SDKs. In TypeScript, `streamObject`
returns lazy streams immediately, before the model call completes. In Go,
`StreamObject` returns only after the stream is fully consumed, and reports
progress through `OnChunk` as the partial object is refined.

For incremental partial objects or array elements, use `StreamText` with
`Output` (`PartialOutput` / `ElementStream`) instead — this is also what the
TypeScript SDK recommends going forward.

```go
// Not recommended: StreamObject blocks until the stream finishes.
result, err := ai.StreamObject(ctx, ai.StreamObjectOptions{
    Model:  model,
    Prompt: "Generate a recipe",
    Schema: recipeSchema,
    OnChunk: func(partial interface{}) {
        // Called incrementally as the partial object is refined.
    },
})

// Recommended: StreamText + Output returns immediately and lets you read
// the incrementally parsed value as chunks arrive, matching TS's lazy
// streamObject.
textResult, err := ai.StreamText(ctx, ai.StreamTextOptions{
    Model:  model,
    Prompt: "Generate a recipe",
    Output: ai.ObjectOutput[Recipe](ai.ObjectOutputOptions{Schema: recipeSchema}),
})
for chunk := range textResult.Chunks() {
    if chunk.Type == provider.ChunkTypeText {
        partial := textResult.PartialOutput() // latest parsed partial value
        _ = partial
    }
}
```

When the stream ends cleanly without a finish part, Go still parses, validates and returns the object (finish reason `other`); TypeScript's `result.object` never settles in that case (S3: a Go call must return). When the stream itself fails, Go closes the step and root spans with the error; TypeScript leaves them open (S7). Laziness itself: S1 (`StreamObject` returns a consumed result).

## Video generation webhook suspension in workflows

TypeScript's `experimental_generateVideo` can durably suspend a Vercel
Workflow DevKit run until a provider webhook fires, resuming the workflow
from durable storage when the video finishes. This depends on the Node-only
Workflow DevKit runtime and has no Go equivalent.

In Go, video generation polls until the job is done (`GenerateVideo`), or you
drive the job yourself with `ai.ExperimentalStartVideo` /
`ai.ExperimentalGetVideoStatus`, which support both polling and webhook
completion (fal and Replicate) outside of a workflow.

Reason: S3: durable suspension needs the Node-only Workflow DevKit runtime.

## Vercel Sandbox OIDC token refresh
`@vercel/sandbox` refreshes the Vercel OIDC token through `@vercel/oidc` by default, writing the refreshed token to the Vercel token cache and `process.env`, and can prompt for local dev credentials. In `pkg/harness/sandbox/vercel` the refresh is opt-in: set `OIDCRefresh` on `CreateSessionOptions`, `ResumeSessionOptions` or `LegacySettings`. The refreshed token, and the project token TS saves to the token cache, are kept in memory in that `OIDCRefresh` value; the Vercel CLI login and the token cache are read only, the CLI login is never refreshed with its refresh token (the error is `Failed to refresh authentication token.: <reason>`), and there is no interactive credential prompt. Without `OIDCRefresh`, the token (`VERCEL_OIDC_TOKEN_FILE`, else `VERCEL_OIDC_TOKEN`) is used as read, also when it has expired. The sandbox follows `@vercel/oidc` 4.0.0 (the version `@vercel/sandbox` 3.9.0 pins); `gateway.VercelOIDCTokenFunc` follows 3.2.0 (the version TS `@ai-sdk/gateway` pins) (S4: owner decision b).

## Vercel OIDC 4.0.0: keyring login and CLI config

`@vercel/oidc` 4.0.0 asks `@vercel/cli-config` where the Vercel CLI keeps its login (`getGlobalPathConfig`, `tryReadAuthConfig`) and, when the CLI stores credentials in the system keyring (`VERCEL_TOKEN_STORAGE` / `credStorage`), runs `vercel project token <project> --format=json [--scope <team>]` to refresh the OIDC token. Go reads the login from `<user data dir>/com.vercel.cli/auth.json` as 3.2.0 did and never runs the Vercel CLI: with keyring storage, pass `OIDCRefresh.AccessToken`. The `@vercel/cli-config` source was not available to compare (not in the TS checkout or the owner-approved packages) (review round 87c).

Reason: S4: owner decision b.

## Vercel OIDC token parse errors

When the Vercel OIDC token payload is not JSON, the cause of the `LocalOidcContextError` carries Go's JSON parse error text (for example `unexpected end of JSON input`), not V8's `SyntaxError` text (`Unexpected end of JSON input`). A missing `VERCEL_OIDC_TOKEN_FILE` file is Go's `open <path>: no such file or directory` (matchable with `errors.Is(err, os.ErrNotExist)`), not Node's `ENOENT: ...` text. The zod issue texts match (review round 87c).

Reason: S3: V8 and Node error texts.

## Code-mode: never-settling promises and in-flight limits
`pkg/codemode` runs model-written JavaScript in a QuickJS-on-WebAssembly sandbox (wazero). Concurrent tool calls that need approval (for example inside one `Promise.all`) are batched into a single interrupt, as in TS. These details differ:

- A script that returns while a call paused for approval is still pending always fails with `DetachedBridgeRequestError`. In TS the outcome depends on worker message timing (S3).
- On platforms other than Linux, macOS and Windows, the default worker cap is 32, because Go cannot read available memory there without cgo (S3).
- A resumed run whose `ToolExecutionOptions` has an empty `ToolCallID` keeps the continuation's outer tool call ID; `ToolCallID` is a v0.5.2 string (S1).
- `SetMaxWorkers(0)` means no concurrency limit, as v0.5.2 documented; TypeScript rejects 0 (S6).
- Tool inputs reach Go tools as JSON: a circular or BigInt input that devalue accepts fails the call with the JSON error; TS passes the JS value (S3: JS values with no JSON form; review round 87e).

## MCP transports
- Transport failures that wrap a Go error (a failed dial, a broken pipe, a request sent before `Connect` on `HTTPTransport`) are `*TransportError` (`transport error: ...`); TS passes the runtime's own error, whose text is Node's. Errors TS creates itself use the TS text (S3).
- `SSETransport.Connect` or `HTTPTransport.Connect` interrupted by `Close` returns an error and leaves the transport closed; TS's `start()` then never settles (SSE) or cannot be interrupted (HTTP) (S3).
- `StdioTransport.Connect` after `Close` starts the server again; TS's `start()` never settles (S3).
- `HTTPTransport.Close` waits for its background goroutines, except one inside an `OnError`, `OnSessionIDChange` or `OnSessionExpired` callback (so the callback can call `Close`), and does not cancel an OAuth authorization the inbound SSE GET started after a 401 (as TS; its failure still reaches `OnError`) (S3: no goroutines in JS).

## fx: libfx runtime

- **Opt-in, not the default.** TS `createFx()` always runs libfx. Go keeps
  the v0.5.x sandbox `fx acp` adapter as the default (`fx.RuntimeSandboxACP`)
  and runs libfx with `fx.Settings{Runtime: fx.RuntimeLibfx}`. Making libfx
  the default would change the built-in tools, the network path and the
  lifecycle state for v0.5.x callers.
- **wasm only.** Go runs libfx's `fx-core.wasm` on wazero. The Node native
  addon (`backend: "native"`) is not available.
- **The credential stays on the host.** The TS host puts the AI Gateway key
  in the core's environment. Go gives the core a placeholder and swaps in
  the real key on the host, only for AI Gateway requests, and removes the
  key from responses.
- **Origin allowlist.** The core's requests, and the redirects they follow,
  may reach only the AI Gateway base URL and libfx's provider origins; TS's
  fetch allows any URL. A Gateway request path that is itself a URL stays a
  path on the base URL, where TS's `new URL(path, base)` would resolve it to
  that other origin.
- **Asynchronous tool-result echo.** Turn parts reach `Emit` from one
  goroutine per turn. TS emits the echo of `submitToolResult` before its
  promise resolves; Go's `SubmitToolResult` returns once the result is saved,
  and the echo follows on `Emit`.
- **Subscription hardening.** Like libfx, Go masks the subscription tokens a
  failed response repeats in its body; it also masks them in response
  headers of any status, masks both the rejected and the refreshed tokens
  after a `401` retry, adds credentials only to the selected provider's
  endpoints (libfx would also authorize Grok endpoints on a codex agent and
  the reverse), bounds OAuth token responses at 1 MiB, and refuses a
  redirect that would carry the credentials to another origin. Of `https://x.ai`
  the core may reach only `https://x.ai/cli/stable`, where the grok provider
  reads the Grok CLI version without credentials.
- **MCP server order.** Go maps have no insertion order, so `MCPServers` are
  connected, and their tools listed, in server-name order unless
  `Settings.MCPServerOrder` gives the TS object's key order. Structured MCP
  tool output is serialized with sorted object keys.
- **Edge cases only the core or a crafted request reaches.**
  - The Responses endpoint check ignores the URL's userinfo and fragment,
    which TS `href.split('?')[0]` keeps.
  - A host tool image with `data: ""` and no `sourceRef` is rejected as an
    invalid tool image; TS keeps it. Go's `ToolImage` cannot tell an empty
    string from an absent one.
  - The `toolStartInput` size limit measures the raw wire bytes, where TS
    measures `JSON.stringify(rawInput)`. They differ only near the 64 KiB
    limit.
  - `realpath` decodes the sandbox's base64 output strictly (standard
    alphabet, padding required); Node's `Buffer.from(..., 'base64')` skips
    characters outside the alphabet. Invalid UTF-8 in the decoded path
    becomes U+FFFD in both. The `base64` command's own output decodes the
    same way in both.
  - When a `bash` `timeout` passes, the error text is what the sandbox
    returns for a cancelled context (usually `context deadline exceeded`);
    TS gets the sandbox's rejection for a `TimeoutError` ("The operation was
    aborted due to timeout").
  - The `glob` tool does not support minimatch extglobs (`@(a|b)`,
    `!(a)`, `+(a)`, `*(a)`, `?(a)`); their characters match literally.
  - Where Node's `path.matchesGlob` throws "Invalid regular expression ...
    Invalid escape" (a segment with a Unicode posix class such as
    `[[:alpha:]]` next to a literal `-`, `,`, `#` or space), Go matches the
    segment instead of failing the tool.
  - Brace patterns cost about what they cost in Node: minimatch's
    second-phase merge is quadratic in the number of expansions, so
    `{a,b}` repeated 17 times takes tens of seconds of CPU in both. Node
    cannot interrupt the synchronous compile; Go stops it when the tool
    call's context ends and the tool fails with the context's error.
    Braces nested thousands of levels deep make Node throw "Maximum call
    stack size exceeded"; Go expands them, slowly, until the context ends.

Reason: S2 / S3 / S1 per item (the fx slice owns this section).

## Harness file reporter
A step's `output` is rebuilt from the step-end telemetry event in a fixed order: text, reasoning, files, tool calls, tool results. TS writes the step's content in stream order, including tool approval requests and responses and the per-part provider metadata, with each part shaped as its TS construction site builds it. Go writes `"input": null` where TS leaves an undefined input out. A Go step result does not record those per-site shapes (coordinator ruling round 87e: stays unless the shapes can be derived per site).

Reason: S4 (coordinator ruling, round 87e).

## Google batch and Perplexity: empty values and fractional counts
`BatchV4ListOptions.Cursor`, `BatchV4StartOptions.WebhookURL`, `BatchV4ListResult.NextCursor` and `BatchV4Status.RawStatus` are v0.5.2 strings, so `""` means unset: Go sends no `pageToken=` or `webhookConfig` for `""` and reports `nextPageToken: ""` as no cursor. Fractional token and invocation counts (accepted, as TS `z.number()`) are truncated toward zero because `types.Usage` and the Perplexity metadata hold integers (S1).

## Accept header
Streaming requests send `Accept: text/event-stream` and other requests send none. TS's `fetch` adds `accept: */*` to every request that sets none (S3: Node runtime default).

## WorkflowAgent root telemetry outside a durable run
TS WorkflowAgent reports its root telemetry in two ways, chosen by `isInWorkflow()`. In a Workflow DevKit run it records the events and reports them when the run ends, with a `call-…` call ID, the final step's fields on the end event, and an `onAbort` for a run that never closed. Outside one it dispatches live: the call ID is the literal `'workflow-agent'`, the end event has no `finalStep` (both TS OTel integrations throw on it), and an abort returned by the model step leaves the root open. Go has no Workflow DevKit and always behaves like the durable report (S3: the Node-only Workflow DevKit runtime).

## Option validation timing
`StreamText` returns an invalid `Instructions` value (a non-system message) as its error, synchronously, as v0.5.2 did. TS `streamText` validates the prompt inside its async run, so the error arrives as an error part or a rejected promise (S6).

## UI message stream: source failure writes an error chunk
When the source of `ToUIMessageStream` fails (any error other than an abort), Go writes one `error` chunk (masked unless `OnError` returns other text) before it ends; TS errors the stream without it. The `StreamTextResult` SSE helpers then end without `data: [DONE]` and return the error, as TS. The chunk-channel helpers do the same when given `UIMessageStreamResponseInit.StreamErrors`, else they end with `[DONE]`. TS clients show the error chunk's text (S4: owner decision, 2026-10-29).

## UI message stream JSON key order
UI SSE events write each chunk's keys in the TS order. Nested objects held in Go maps (provider metadata, tool input and output, data) and keys TS does not create are written in sorted order (S3: Go map order; review round 87e).

## ToUIMessageStream on a raw provider stream

`ai.ToUIMessageStream` also accepts a raw provider `TextStream` (one that does
not start with a `ChunkTypeStart` part), which TS `toUIMessageStream` does not
take. Go frames such a stream: it writes a `start` chunk (after the first
source part arrives), opens and closes text and reasoning blocks, writes
`finish-step` for the provider's `finish` and a final `finish`, and writes an
incomplete-stream `error` chunk when the stream ended without output. A
source that starts with a start part (`StreamText`, harness and
`NewStreamTextResultFromParts` streams) is mapped one to one, as in TS
(owner ruling 2026-10-30). In both modes a text delta with no open block gets
a `text-start` first, because Go providers may stream text without one; TS
forwards the delta alone (review round 71).

Reason: S4 (owner 2026-10-30, option a) + S6 (v0.5 providers may stream text without block parts).

## RuntimeContext defaults to nil

TS `generateText` and `streamText` default `runtimeContext` to `{}`, so
`onStart`, `onStepStart`, the tool events and every step carry `{}` when the
caller sets none. Go leaves `RuntimeContext` (and the deprecated
`ExperimentalContext`) nil: a nil `interface{}` is the idiomatic "not set",
and v0.5.x callers check it with `== nil` (owner preference, review round
71). `ToolsContext` defaults to an empty map, as in TS.

Reason: S4: owner preference (R72 / R73).

## Abort keeps the parts produced before it

When the caller cancels while a step is streaming, Go's full stream and UI
stream keep every part the model produced before the abort (the step's
`start-step` and deltas), then the `abort` part. TS drops parts that were
still queued inside its stream pipeline when the signal fired, so its
snapshot for an abort in the second step shows the first step and the
`abort` part only. Which parts TS drops depends on its stream queue timing,
not on a rule; `OnAbort`, the recorded steps and the result are the same
(review round 72).

Reason: S3: TS stream queue timing.

## Tool call input keeps undeclared keys
TS zod object schemas strip keys they do not declare from the parsed tool input. Go strips them for the 20 Anthropic provider tools whose TS schema is a flat `z.object` and whose Go schema declares the same keys (bash, text editor, computer, code execution 20250522, tool search, web fetch, web search, advisor). Other provider tools keep undeclared keys: discriminated unions (memory, code execution 20250825 / 20260120), nested schemas and schemas not audited key by key, where a Go schema missing a key TS keeps would silently drop an argument of a locally executed tool (S7). Go user tools match TS `jsonSchema()` tools, which do not strip either (review round 87e).

## Reasoning lists hold reasoning text only

TS `StepResult.reasoning` and the result's `reasoning` are
`Array<ReasoningPart | ReasoningFilePart>`. Go's `Reasoning` fields are
`[]types.ReasoningContent` and hold the reasoning parts. The reasoning file
parts are returned by `StepResult.ReasoningFiles()` (from `Content`) and are
in the telemetry `ReasoningFiles` (review rounds 72, 73).

Reason: S1: `Reasoning []types.ReasoningContent`.

## ConsumeStream returns the error

TS `consumeStream()` swallows stream errors (it calls `onError` when given
one). Go's `StreamTextResult.ConsumeStream() error` returns the error, the Go
form of `onError`; ignore the return value for TS's behavior (review
round 73).

Reason: S1: v0.5.2 `ConsumeStream() error`.

## Merged UI message stream order

When `CreateUIMessageStream` merges several sources (`writer.Merge`), TS's
exact interleaving follows its microtask queue. Go forwards every chunk and
keeps each source's own order, but chunks of different sources interleave
by goroutine scheduling (review round 73).

Reason: S3: microtask versus goroutine scheduling.

## Message metadata merge with non-object values
Metadata merges like TS `mergeObjects`. Where TS throws (`key in base` on a string, number or boolean base followed by a value with keys), Go replaces the metadata as v0.5 did (S6). A string's spread splits non-BMP characters into UTF-16 halves in TS; Go writes U+FFFD for each half (S3; round 87e).

## UI message stream end event finish reason
The UI stream end event's `finishReason` is a `types.FinishReason` from `ToUIMessageStream` (`""` when none) and the finish chunk's value from `CreateUIMessageStreamWithOptions` (`nil` when none), as in v0.5. TS reports the string or `undefined` in both (S6).

## Anthropic batch results of id-named provider tools across processes
A Go provider tool that keeps its constructor id as `Name` (`anthropic.bash_20250124`) has no TS counterpart: TS rejects a batch tool whose name differs from its wire name. Go accepts it and reports `Name` only when the Provider that started the batch reads the results (up to 1024 batches). Results read elsewhere report the wire name (`bash`). Name the tool `bash`, as TS callers do, to get the same name everywhere (S3).

## StreamText tool context failure ends the run

When a tool's `ContextSchema` rejects its tool context, TS
`executeToolsFromStream` catches the throw and enqueues an `error` part. The
TS stream goes on: the step finishes with no tool output, so the run ends
with `finish` and `onEnd`. Go ends the run with the `ValidationError`: the
stream stops with no `finish-step` or `finish`, `OnEnd` is not called, and
`Err()` returns the error. `OnError` is called once, as TS calls `onError`
for the error part. This keeps StreamText in line with `GenerateText` and the
agents, where a tool context failure fails the call (owner decision,
2026-10-28).

Reason: S4: owner decision, 2026-10-28.

## JSON payloads with `__proto__`

Go accepts JSON with a `__proto__` key or a `constructor.prototype` member
in provider responses and stream chunks. TS `secureJsonParse` rejects those
payloads (a `JSONParseError`) as a guard against JavaScript prototype
pollution. Go `encoding/json` decodes into maps and structs, which have no
prototypes, so there is nothing to guard against, and rejecting the
payloads would only turn valid JSON into errors.

This difference covers provider responses and stream chunks only. Prompt
conversion follows TS: a stringified Google Interactions tool-call input with
such a key is sent as `{value: input}`, as TS `safeParseToolArgs` does when
`secureJsonParse` throws.

The Gemini prompt converter (`generateContent`, Google and Vertex) accepts a
string tool-call input with such a key for `code_execution` and server tool
calls, where TS `secureJsonParse` throws. In Go, `ToolCallContent.Input` is
always the wire text, also for inputs that TS holds as objects and passes
through without parsing, so throwing would reject inputs that TS accepts.

This also covers JSON in model output that core parses: tool-call inputs,
GenerateObject / StreamObject text, partial JSON and DecisionLanguageModel
answers. TS parses these with `safeParseJSON` and treats such a key as
invalid JSON (review round 89).

Reason: S3: Go decoders build no prototypes.

## StreamText reads the provider stream without a reader

`StreamText` reads the model's stream into its buffer whether or not anyone
reads the result, so callbacks such as `OnFinish` run without a reader, as in
v0.5. A TS `streamText` stream that nobody reads stalls the model call
under backpressure. So after a client disconnect, and after a
`ConsumeSSEStream` callback returns, the Go model call keeps running until
the `StreamText` ctx ends. Pass `r.Context()` (or another ctx you cancel) to
stop it, or use `StreamTextLowMemory` for a bounded buffer with
backpressure (review round 79).

Reason: S6: v0.5 callbacks run without a reader (+S3: WHATWG backpressure).

## Invalid tool call input that is not a JSON object

TS keeps the model's raw text as the `input` of an invalid tool call, and of
its tool-error, when the text does not parse as JSON (`'invalid json'`; `''`
for empty input). Go keeps the raw text in `ToolCall.RawArguments` and
`ToolCallContent.Input`, and the tool-call part's JSON `input` is that text,
but `ToolCall.Arguments`, `ToolResult.Input` and `ToolErrorContent.Input` are
maps: the invalid call's tool-error has no `input`, and an empty input is
`{}`. Valid JSON that is not an object (`[1,2]`, `"text"`) is an invalid call
in Go also for a tool without `Parameters`, where TS (no schema validation)
accepts it. The validator text inside a `TypeValidationError` is Go's
(`$.city: required: property is missing`), not zod's issue list, and a
`JSONParseError` carries Go's parser message, not the JavaScript
`SyntaxError` text (review round 79).

Reason: S1 (`map[string]interface{}` inputs) and S3 (zod issue lists, V8 `SyntaxError` texts).

## Tool output JSON key order in replayed prompts

A tool result's JSON output that the SDK serializes into the request text
(openresponses `function_call_output`, the OpenAI-compatible prompt
converters) keeps Go's map key order, not the TS object's insertion order.
The values are the same. The TS replays "should convert tool message with
json output", "should convert user - assistant (tool call) - tool message
chain" and "should convert a tool roundtrip with follow-up assistant
message" (openresponses) are skipped on it (review round 79). The google Interactions converter's `function_result` text (`JSON.stringify(output.value)`) follows the same rule; the TS assertion in "serializes a json tool result to a stringified payload" is marked n/a (review round 87d).

Reason: S3: Go map order.

## Embedding usage across EmbedMany batches
When a provider sends no embedding usage for a call or for some `EmbedMany` batches (Google never does), `Usage.Tokens` is the sum of the reported batches (0 when none), as in v0.5.2, and the telemetry usage attribute is dropped. TS sums `usage ?? {tokens: NaN}`, so its result is NaN (S6: v0.5.2 callers sum, compare and `json.Marshal` the count, and `json.Marshal` fails on NaN; coordinator ruling round 87e).

## Legacy telemetry tool spans on error
When a call fails, Go's `LegacyOpenTelemetry.OnError` ends the tool spans that are still open with the error status, so they are exported. TS `LegacyOpenTelemetry.onError` deletes the call state without ending them, so they are never exported (S7: TS loses the spans of a failed call; review round 87e).

## Provider option spellings kept from v0.5
Alibaba also reads `providerOptions["openai-compatible"]` / `["openaiCompatible"]`, the raw `enable_thinking` / `thinking_budget` / `parallel_tool_calls` / `preserve_thinking` spellings (with a `deprecated` warning) and the common `user` / `reasoningEffort` / `textVerbosity` options, which it sends; TS alibaba parses only the camelCase `providerOptions.alibaba` keys. Z.ai still forwards `user` and `verbosity`, which TS `transformZaiRequestBody` drops. v0.5.2 read and documented these spellings (S6, coordinator ruling round 87e).

## Hugging Face byte image data
A Hugging Face image part with byte data (`FileData.Data`) is sent as a base64 data URL. TS interpolates the `Uint8Array` into the data URL, which produces a comma-separated byte list that the API rejects (S7: Go does not copy a TS bug that breaks a working call; review round 87e).

## Provider option warning order

Perplexity reports its unsupported-option warnings in sorted option-name
order. TS follows `Object.keys(providerOptions.perplexity)`, the object's
insertion order, which a Go map does not keep (the wire replay of "warns
about unsupported options without adding fields to the request" is skipped
for it; review round 82).

Azure reports its warnings for OpenAI options given under `providerOptions.azure` (Speech and MAI routes) in the TS option-shape order, not the caller's object key order (review round 88).

Reason: S3: a Go map has no key order.

## Struct-tag schemas: Go-only choices

`schema.NewStructSchema` / `NewSimpleStructSchema` generate the JSON Schema
TS sends for the matching zod object, with these Go choices where no zod
schema is the twin: a described required recursive reference is
`{"description", "allOf": [{"$ref"}]}` inline, as the zod 3.25.76 `zod/v4`
core the SDK pins emits it (zod 4.4 and later move it to a `definitions`
entry, so TS output depends on the caller's zod);
`float32` / `float64` are a bare `number` (zod `z.number()`, not
`z.float32()` bounds); `time.Time` is `format: date-time` without zod
`z.iso.datetime()`'s Z-only `pattern` (encoding/json accepts offsets);
`[]byte` is a plain `string` without the zod `z.base64()` keywords; pointer
slice elements are not nullable; `validate:"required"` also rejects zero
values (go-playground), which JSON Schema `required` cannot state; and
`validate` rules after `dive` and alternatives (`a|b`) are left out of the
schema (review rounds 82 and 83).

Reason: S3: TS output depends on the caller's zod version; the rest are Go types with no zod twin.

## URL parsing: three IDNA edge cases

Core prompt conversion serializes URL file parts with a Go WHATWG URL
parser (`pkg/internal/urlnorm`), differential-tested against Node 24
`new URL(x).href` on a 5.2k-case corpus and 720k fuzz inputs. Three classes
of non-ASCII domains with an `xn--` label after mapping still differ: Go
rejects `xn---xii` (RFC 3492-valid, Node accepts), accepts
`xn--xn--xiiffxn--255ab` (Node's Ada decoder rejects it), and applies the
Bidi rule to a label that decodes to Arabic Extended-B code points (Ada
skips it) (review round 84).

Reason: S4: R86B ruling 1.

## Typed URL fields

TS treats a plain string file `data` that does not parse as a URL as
base64 inline data. Go has no field that may hold either:
`FileContent.URL`, `ImageContent.URL`, `FileContentBlock.URL` and
`FileData{Type: url}` are URLs and bytes are `Data`, so a Go URL that does
not parse fails with `Invalid URL`, as a TS tagged `{type: 'url'}` part does
(review round 84).

Reason: S4: R86B ruling 2 (+S1).

## Prompt file download errors

The default prompt-file downloader (`ai.DefaultDownload`,
`ai.CreateDownload`) refuses the URLs TS `validateDownloadUrl` refuses
(non-http(s)/data schemes, localhost and `.local`/`.internal` names, private,
loopback, link-local and metadata addresses in every IPv4/IPv6 spelling) and
also resolves host names first, but reports them as the v0.5
`*providererrors.SSRFError` texts (`URL scheme "file" is not allowed: only
http, https, and data are permitted`, `URL resolves to loopback address
127.0.0.1`) instead of TS `DownloadError` texts. The error type and text are
kept from v0.5.2 (exported, security path) (review round 84).

## Fractional counts in integer fields
Where a Go field that v0.5.2 already exposed is an integer, a fractional count from the API is truncated; TS keeps the fraction: `Usage` token counts (`*int64`), Gateway `GenerationInfo` latencies and token counts, `SpendReportRow` counts, `RealtimeClientSecret.ExpiresAt`, a Gateway video SSE error `statusCode` (`SSEVideoEvent.StatusCode *int`; a fractional value fails the event parse), and decision usage token counts (`provider.DecisionUsage`, the v0.5.2 `EvaluationUsage` with `*int` fields; TypeSafe AI and the other decision models) (S1: exported integer field types; review rounds 90, 95).

## Gemini non-streaming string functionCall args
When a non-streaming Gemini response carries `functionCall.args` as a string, Go uses it verbatim; TS JSON.stringify's the value into a quoted JSON string that no tool can parse as arguments (S7: TS defect; review round 90).

## Invalid video operation references
HeyGen, Google and Vertex `DoStatus` return a plain Go error when the opaque operation JSON does not decode; TS reads the operation object and fails later with a JS TypeError (S1: the operation is opaque `json.RawMessage`; review round 90).

## Gemini streamed tool arguments with conflicting paths
When streamed Gemini `partialArgs` address a path that conflicts with an earlier value (a key under a string or number, a key on an array, an index on an object, a string continuation of a non-string), TS either throws a TypeError or silently builds corrupted arguments (`"[object Object]x"`, keys `JSON.stringify` drops, text deltas that are not JSON). Go fails the stream with an error at that entry (S7: TS defect, the corrupted arguments would reach the tool; review round 90).

## Z.AI PrepareRequest and ConvertResponse
TS `ZaiChatLanguageModel` inherits `prepareRequest` / `convertResponse` from the OpenAI-compatible model; they skip Z.AI's call-option normalization (penalties, seed, non-auto tool choice that Z.AI does not support) and its finish-reason mapping, so the body differs from what `doGenerate` sends. Go does not expose them on `zai.LanguageModel` (S7: TS defect; review round 90).

## Vertex Anthropic missing project or location
TS builds `https://undefined-aiplatform...` and sends the request; Go returns an error before sending (S7: TS defect; review round 90).

## Bedrock base URL from an empty endpoint variable
TS uses an empty `AWS_ENDPOINT_URL` / `AWS_ENDPOINT_URL_BEDROCK_RUNTIME` value as the base URL (an invalid URL); Go ignores an empty variable (S7: TS defect; review round 90).

## Bedrock image text-to-image without a prompt
Bedrock image text-to-image without a prompt sends `text: ""`; TS omits the key (S1: plain string field; review round 90).

## Anthropic MCP tool result without its tool use
TS crashes ("reading 'toolName'") on an `mcp_tool_result` block without its `mcp_tool_use`; Go converts the result without the tool name (S7: TS defect; review round 90).

## Bedrock Converse JSON instruction schema key order
The JSON-instruction text Bedrock Converse injects for a JSON response format prints a schema given as a Go map with sorted keys; TS keeps the object's insertion order (S3: Go map iteration order; pass an ordered schema to keep the order; review round 90).

## Codex tool description ""
A harness tool with `Description: ""` gives the same Codex turn fingerprint as one without a description; TS includes `description: ""` (S1: `harness.ToolSpec.Description` is a plain string, and a presence flag would break unkeyed literals; review round 90).

## UI message chunk validation on client reads
TS chat transports validate every received chunk against `uiMessageChunkSchema` and report an `AI_TypeValidationError` for a chunk of the wrong shape; Go's `ReadUIMessageStream` and `WorkflowChatTransport` accept any JSON object. A frame that is not JSON is an `AI_JSONParseError`-style error in both, but Go's parser message is not V8's (S3: the TS transports are browser `useChat` APIs, and the parser text is V8's; review round 90).

## DNS protection on by default
TS `2ebc78b654` removed the DNS-pinned default download transport and asks Node.js callers to inject `guarded-fetch`. Go keeps validated, DNS-pinned downloads (`fileutil.SafeTransport`) as the default for every untrusted download, prompt files and the generated file URLs a model returns included (those use `ExperimentalDownload` when it is set). A caller-supplied transport takes over connect-time validation, as an injected `fetch` does in TS: `ai.DownloadOptions.Transport` is the opt-in counterpart of TS `createDownload({ fetch })` and keeps URL, DNS pre-check and redirect validation. URL validation, redirect checks and header isolation apply either way. TS added no opt-in flag, so Go has no new option. The TS tests that route Vertex image and tool-result downloads through a caller `fetch` are skipped in the wire replay for this reason (S2: security is never traded for parity; review round 91).

## MCP OAuth: DNS protection without a custom fetch
Go always dials untrusted MCP OAuth discovery, token and registration hops through the DNS-pinned transport unless the caller supplies an HTTP client, so there is no runtime-dependent "requires a custom fetch with connect-time DNS validation" error (TS `88b95757c1`, and on Node.js too since `2ebc78b654`) (S2; review rounds 91, 92).

## toolbash command execution
`toolbash` runs commands with `SandboxSession.Spawn`, a per-stream output bound and a process-group kill instead of TS `sandbox.run()`, which would buffer unbounded command output in memory. A timed-out command ends with exit code 124 in Go; with the TS Vercel adapter the run rejects and the tool returns an error (S2; review round 91).

## LangSmith deployment stream reconnect
`LangSmithDeploymentTransport` does not reconnect a dropped run stream. langgraph-sdk `streamWithRetry` reconnects up to 5 times with a GET on the response `Location` and `Last-Event-ID`, and its idle watchdog reconnects a half-open socket after heartbeats stop; Go reports the stream error. The initial request's connection retries match TS. The connection error always says `Original error: fetch failed` (undici's message for every network failure); the Go transport error is its `Unwrap()` (S3: Node fetch internals; S5 for the reconnect protocol; review round 91).

## ExtractJSONMiddleware without text-start
`ExtractJSONMiddleware` extracts JSON from text deltas that have no `text-start` and flushes them at the end of the stream, as v0.5.2 did; TS passes such deltas through unchanged (S6; review round 91).

## ExtractReasoning separator
`ExtractReasoningOptions.Separator: ""` means the default `"\n"`; TS honors an explicit empty separator (S1: v0.5.2 string field; review round 91).

## Embed and rerank end events of failed attempts
`Embed`, `EmbedMany` and `Rerank` fire an end event with `Error` for each failed provider attempt. TS fires none and leaves that attempt's span open when a retry succeeds, which leaks the span (S7; review round 91).

## WorkflowChatTransport request headers
`WorkflowChatTransport` POSTs with `Content-Type: application/json` and `Accept: text/event-stream`, as v0.5.2 did; TS sends only the configured headers (so `fetch` sends `text/plain;charset=UTF-8` for the string body and `accept: */*`). The prepared headers still win (S6: a server that parses only JSON bodies would stop reading the request; review round 91).

## CreateIDGenerator empty fields
`CreateIDGenerator` treats `Prefix: ""`, `Size: 0`, `Separator: ""` and `Alphabet: ""` as unset; TS uses them (an explicit `''` prefix gives `-<id>`, size 0 an empty id, an empty separator throws) (S1: v0.5.2 plain fields; review round 91).

## Empty StopWhen slice
An explicit empty `StopWhen` slice is the default (`StepCountIs(1)`; a `WorkflowAgent` uses the agent's condition or its default of 20 steps), not "no stop condition" as in TS. Sites: `stop_condition.go`, `StreamText`, `GenerateText`, the `ToolLoopAgent` loop and `WorkflowAgent` (S6: matching TS would turn a call that stops after one step in v0.5.2 into an unbounded tool loop for code that builds the slice with `make`; review round 91).

## GenAI OpenTelemetry empty-string attributes
The GenAI OpenTelemetry integration drops `gen_ai.provider.name` and `gen_ai.response.id` when the provider or response id is `""`, and agent span naming treats a `""` function id (or an `AgentSpanNameFunc` returning `""`) as unset; TS records the empty values (S1: plain v0.5.2 string fields; review round 91).

## Anthropic custom content parts
The Anthropic prompt converter forwards `providerOptions.anthropic` of a caller-built custom part of any kind as the block; TS drops every custom part that is not `anthropic.fallback` (S6: shipped in v0.5.2; review round 91).

## Chunk schema error text
A chunk or Responses chunk that fails its schema reports a compact Go issue text (the first failing member's code, path and message) and the compacted frame; TS `TypeValidationError` writes `JSON.stringify(value)` and zod's pretty-printed issue list rooted at `invalid_union` (S3: zod issue lists, error text only; review round 91).

## Text and reasoning deltas of never-started blocks
`StreamText` accepts a text or reasoning delta whose block never started (no `text-start` / `reasoning-start`) and records it, because v0.5 providers stream text without block parts; an end part of a never-started block is accepted too. TS emits an error part `text part <id> not found` and does not record it. A delta or end of a block that started and already ended matches TS (S6; review round 91).

## Non-finite numbers in UI messages
Go's JSON values cannot hold Infinity or NaN. `ValidateUIMessages` reports a non-finite number (a Go `+Inf` / `NaN`, or a JSON number out of range such as `1e999`) anywhere in the messages as one `ValidationError` with the TS text `Invalid JSON value. Expected null, a string, a finite number, a boolean, an array, or an object.`, without the issue path. TS reports it only in provider, tool and citation metadata, with its path, and ignores such values in unknown properties and in `input` / `output` (S1; review round 91).

## Claude Code resume state from v0.5.2
TS rejects lifecycle state whose bridge coordinates carry `token` instead of `privateKey`. Go accepts the v0.5.2 Claude Code state, never uses the token, and resumes by respawning the bridge with a new key pair instead of attaching (S6; review round 91). The other bridge adapters reject token state, as TS does.

## DownloadError cause text
`DownloadError.Error()` writes the cause's message; TS writes `${cause}`, which prefixes the error name (`Error: msg`) (S3; review round 91).

## Legacy V4 prompt telemetry details
The legacy `ai.prompt.messages` attribute serializes the step messages the SDK already normalized. A nested tool-result file keeps the Go `ToolResultOutput` JSON (TS leaves `Uint8Array` data as an index object), and an empty `System` string is no system message (S3; review round 91).

## Bedrock Converse task budget
Bedrock Converse forwards `providerOptions.anthropic.taskBudget` as `output_config.task_budget` with the task-budgets beta for Anthropic models; TS Bedrock ignores `taskBudget`. Go keeps the v0.5.2 behavior (S6; review round 91).

## Header-only API key authentication
When `Config.Headers` carries the credential header (`x-api-key` or `Authorization`), the Anthropic provider and the other providers that use `providerutils.RequestAuthHeader` send it and skip the missing-key `LoadAPIKeyError`; TS `getHeaders` still calls `loadApiKey` and throws `AI_LoadAPIKeyError` before the request. Go keeps the v0.5.2 header-only authentication (S6; review round 91).

## Vertex Anthropic labels header key order
The `x-vertex-ai-labels` header is the base64 of the labels JSON with keys in sorted order (a Go map); TS keeps the insertion order of the labels object, so the header bytes can differ. Vertex reads the same labels (S3: Go map order; review round 91).

## xAI cost metadata
Go also reports `providerMetadata.xai.cost` (`inputTokensCost`, `outputTokensCost`, from `usage.input_tokens_cost` / `output_tokens_cost`) on xAI Responses generate and stream finish results. TS has no such key. v0.5.2 shipped it and the xAI provider docs document it (S6; review round 91).

## xAI video response warnings
When a completed xAI video status response carries a `warnings` array, Go returns each entry as a warning of type `provider-warning`; TS returns `warnings: []` (S6: v0.5.2 behavior; review round 91).

## OpenAI-compatible namespace for provider options
Z.AI (`doSample`, `thinking`, `requestId`, `userId`), Fireworks (`thinking`, `reasoningHistory`, `promptCacheKey`, `serviceTier`) and every DeepSeek option are also read from `providerOptions["openai-compatible"]` / `["openaiCompatible"]` merged under the provider key (the provider key wins); TS reads them only from `providerOptions[<name>]`. DeepSeek also emits the deprecated `openai-compatible` key warning, which TS DeepSeek never emits (S6: v0.5.2 behavior; review round 91).

## Ordered schemas inside provider options
Provider option values are read through their JSON form (so Go-typed literals work), which sends an ordered schema given inside provider options (a Moonshot dynamic tool `inputSchema`, an OpenAI `textFormat` / `textFormatUpdate` schema) in Go map key order; an `outputSchema` in OpenAI tool options keeps its order (S1; review round 91).

## Media request body passthrough keys
Media providers (AssemblyAI, BFL, ByteDance, Gladia, fal, KlingAI, Luma, Replicate, Rev.ai) send their request bodies in TS key order, but passthrough provider-option keys go out sorted, since a Go map keeps no insertion order (S1; review round 91).

## Tencent SubAppId and serialization
TS accepts `subAppId` as `number | string`. Go's `tencent.Config.SubAppID` is a string of decimal digits, with the same validation (`Tencent VOD SubAppId must be a positive integer.`) (S1). A serialized Tencent chat model is restored from its base URL and headers; the API key is loaded again from `Config.APIKey` or `TENCENT_TOKENHUB_API_KEY` and is never serialized, as for the other OpenAI-compatible wrappers (review round 91).

## Deepgram error data request id
Deepgram error `Data` keeps the v0.5 `requestId` key beside the TS `request_id` (S6; review round 91).

## LangGraph run stream invalid event data
A LangGraph run stream event whose data is not JSON fails the stream with `langchain: invalid event data: <decode error>`; langgraph-sdk fails it with the `JSON.parse` SyntaxError text of the JS engine (S3: V8 error texts; review round 92).

## UI message validation issue text
`ValidateUIMessages` reports the first issue of the first invalid message as one `ValidationError` whose text is `<path>: <message>` (for example `[1].id: Invalid input: expected string for id`). TS throws zod's issue list, which holds every issue of that message or part (for `{}`: id, role and parts) (S3: zod issue lists, error text only; review round 92).

## Anthropic AWS settings checked at creation
`anthropicaws.New` returns a `LoadSettingError` when the workspace ID (`WorkspaceID` / `ANTHROPIC_AWS_WORKSPACE_ID`) is missing, and when neither `BaseURL` nor a region is set. TS `createAnthropicAws` succeeds and throws when a model is created (region) or a request is made (workspace ID). Go keeps the v0.5.2 constructor error (S6; review round 92).

## Open Responses accepts extra provider options
Go's Open Responses model also reads `strictJsonSchema`, `textVerbosity`, `store`, `serviceTier`, `previousResponseId`, `conversation`, `include`, `logprobs`, `maxToolCalls`, `metadata`, `parallelToolCalls`, `user`, `instructions`, `promptCacheKey`, `promptCacheRetention`, `safetyIdentifier`, `truncation`, `contextManagement` and `allowedTools`, under the provider's key and the `openai` / `openResponses` / `open-responses` aliases, and sends them. TS parses only `reasoningEffort` and `reasoningSummary` under the provider's own key and always sends `strict: true`. v0.5.2 read and sent these options (S6; review round 92).

## Realtime millisecond fields are integers
`provider.RealtimeServerEvent.StartMs`, `EndMs` and `OffsetMs` are `*int` fields of a v0.5.2 public type, so a fractional value from the wire is truncated; TS keeps the JS number. The raw event keeps the exact value (S6; changing the field types would also break v0.5.2 code at compile time; review round 92). The realtime usage token counts, new in v0.6, keep the JS number (`*float64`).

## Empty API key settings
An empty `Config.APIKey` and an empty API key environment variable count as unset: the call fails with the missing-key `LoadAPIKeyError` before any request. TS `loadApiKey` returns an explicit `''` key, and an empty environment variable, and sends the request with it (S1: `APIKey` is a plain v0.5.2 string field; S6: v0.5.2 treated an empty environment variable as missing too; review round 92). A credential header in `Config.Headers` still authenticates (see "Header-only API key authentication").

## Gladia response body
Gladia's `TranscriptionResult.Response.Body` carries the final poll response. TS returns no response body for Gladia. v0.5.2 returned it, and the same data is in `ProviderMetadata["gladia"]` (S6: v0.5.2 runtime contract; review round 93).

## Audio sample rate is an int
`provider.AudioFormat.Rate` (the sample rate of an audio input or output stream) is a `*int` field of a v0.5.2 public type, so a fractional rate from the wire is truncated; TS keeps the JS number. Sample rates are whole numbers of Hz in practice (S6: changing the field type would break v0.5.2 code at compile time; review round 93). The `SpeechStreamUsage` counts, new in v0.6, keep the JS number (`*float64`).

## OpenAI Responses image detail
An OpenAI Responses image part sends `providerOptions.openai.imageDetail` (or `detail`) only when it is a non-empty string. TS forwards the value as given, so an empty string or a non-string value is sent as `detail`. Go builds the part as `responses.UserImageURLPart`, whose `Detail` is a v0.5.2 exported `string` field with `omitempty`, so it cannot carry `""` or a non-string (S6: changing the field type would break v0.5.2 code at compile time; review round 93).

## LangGraph multimodal run stream messages
A user message with image or file parts goes to a LangGraph deployment with `content` holding the content blocks. TS builds it with `new HumanMessage({ contentBlocks })`, and RemoteGraph serializes that as `content_blocks` with no `content` (`response_metadata: { output_version: "v1" }`). The server's message coercion then loses the content: `@langchain/core` `coerceMessageLikeToMessage` gives `content: []`, and Python `_convert_to_message` requires `content` (S7: the TS form drops the user's message; review round 94).

## Streaming audio input is cancelled on failure
When `ExperimentalStreamTranscribe` or `ExperimentalStreamTranslate` fails, Go calls `Cancel` on the caller's `Audio` stream, even after the model took the stream. TS cancels the input only while no model holds a reader: a locked `ReadableStream` rejects the cancel, and the model's cleanup owns the stream. v0.5.2 documented the Go behavior ("failures cancel the caller's Audio stream", the `ExperimentalStreamTranscribe` and `ExperimentalStreamTranslate` doc comments at a0f9d3f9, and `fail` calls `opts.Audio.Cancel(err)`), and a caller's audio producer may rely on that cancel to stop. Matching TS would leave that producer running when a provider does not cancel the input itself (S6: v0.5.2 runtime contract; review round 94). `ExperimentalStreamSpeech`, new in v0.6, follows TS.

## Streaming transcription audio wrapper
Unless telemetry is disabled (`IsEnabled: false`), `ExperimentalStreamTranscribe` passes the model a byte-counting wrapper around `Audio`, even when no telemetry integration is configured. TS passes the original stream when no integration handles the end event. v0.5.2 wrapped whenever telemetry was enabled (a0f9d3f9 `pkg/ai/stream_transcribe.go` 305-308) and published the end event, with `AudioByteLength`, to diagnostics-channel subscribers without any integration (`FireOnEnd` publishes before the integrations, `pkg/telemetry/registry.go` 2730). The [telemetry guide](../03-ai-sdk-core/60-telemetry.mdx) documents the `onEnd` diagnostics event for `ExperimentalStreamTranscribe`. Passing the original stream would give a v0.5.2 diagnostics subscriber no byte count. The wrapper only forwards `Next` and `Cancel` (S6: v0.5.2 runtime contract; review round 94).

## Option keys match case-insensitively
Provider options and other caller-built values that Go decodes into option structs with `encoding/json` match keys without regard to case, so `{"openai": {"Quality": "hd"}}` sets `quality`; TS's zod schemas ignore a differently cased key. v0.5.2 decoded them the same way (a0f9d3f9: `extractOpenAIImageProviderOptions` round-trips the map through `json.Marshal` / `json.Unmarshal` into `OpenAIImageModelOptions`, whose `Quality` is `json:"quality"`), so callers may rely on it (S6: v0.5.2 runtime contract). Provider responses are decoded with exact keys, as zod does (review round 94).

## Azure Speech transcription phrases metadata
`providerMetadata.azure.phrases` is a v0.5.2 exported `[]AzureSpeechPhrase` with `omitempty` fields. A phrase member that is null on the wire (`offsetMilliseconds`, `locale`, `speaker`, ...) or an empty `words: []` is left out, while TS reports the zod-parsed phrase with the null or empty array kept. Changing the type would break v0.5.2 callers that type-assert it (S6; review round 94).

## ToolLoopAgent per-call deprecated tool callbacks
A per-call `OnToolCallStart` / `OnToolCallFinish` (deprecated) runs after the agent's `OnToolExecutionStart` / `OnToolExecutionEnd`. TS drops the per-call `experimental_onToolCallStart` / `experimental_onToolCallFinish` when the agent settings define the stable callback (generateText reads `onToolExecutionStart ?? experimental_onToolCallStart`). v0.5.2 fired both: `pkg/agent/toolloop.go` at a0f9d3f9, `resolveAgentToolExecutionStart` / `resolveAgentToolExecutionEnd` (lines 111-123) picked the per-call callback and `mergeCallbacks` (lines 61-82) merged it with the settings callback through `mergeListener` (settings first) in Generate, GenerateAgent and Stream (S6: v0.5.2 runtime contract; review round 95).

## Response body idle timeout
Node's fetch (undici) fails a response whose body sends nothing for 5 minutes (`bodyTimeout`); Go's default HTTP client waits until the call's context ends. TS in other runtimes (browsers, edge) has no such limit either. Set a context deadline or `Timeout` to bound a call (S3: runtime fetch default, not SDK code; informational; review round 95).

## Features that are TypeScript-only (not ported)

- **OpenAI Live over WebRTC** — the browser transport for OpenAI's realtime
  API. The Go SDK only implements the server-side WebSocket transport
  (`gpt-live-1` via `ai.ConnectRealtime`), which covers server-side and
  backend use cases; WebRTC is a browser-only transport with no Go runtime
  equivalent.
- **`@ai-sdk/harness-cline` and `@ai-sdk/harness-pi`** — these harness
  adapters run vendor Node SDKs in-process (they embed a Node.js runtime and
  the vendor's own TypeScript SDK). There is no Go equivalent; use the
  TypeScript SDK for Cline or Pi harness integrations.
- **Exported model catalogs (`googleVertexAnthropicModelCatalog` and the
  other `ModelEntry` catalogs)** — TS exports capability metadata objects; Go
  has no catalog API. Runtime behavior (for example Claude Fable 5.2 on Vertex
  Anthropic) comes from the Anthropic capability rules, as in TS.
- **Baseten `performanceClient`** — a Node NAPI addon
  (`@basetenlabs/performance-client`); Go embeddings always use the
  OpenAI-compatible HTTP endpoint (S3; review round 91).
- **DeepSeek batch API / extra Files methods** — TS's `@ai-sdk/deepseek` does
  not implement these either, so this is parity, not a gap; the existing
  DeepSeek file support already matches TS.

Reason: S5.

## Streaming pattern: Next() instead of io.Reader

This is a longstanding, deliberate Go-idiom difference (not new in v0.5.0):
`provider.TextStream` exposes `Next()` / `Err()` / `Close()`, not an

rationale.
