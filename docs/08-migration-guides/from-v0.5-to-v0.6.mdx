# Migrate Go AI SDK v0.5.x to v0.6.0

v0.6.0 catches up with the TypeScript AI SDK `ai@7.0.153`. Most v0.5.x code
compiles and runs unchanged. This page lists the changes that can need an
edit.

## Compile-time changes

### GenerateObject / StreamObject: MaxRetries is now a pointer

**Impact:** compile error if you set `MaxRetries` as a plain int.

`GenerateObjectOptions.MaxRetries` and `StreamObjectOptions.MaxRetries`
changed from `int` to `*int`, matching `GenerateTextOptions.MaxRetries` and
the TS `maxRetries` option. nil uses the default of 2 retries. An explicit `0`
now disables retries (before, `0` selected the default, so retries could not
be turned off). A negative value returns `*errors.InvalidArgumentError`.

**Before:**

```go skip-compile
result, err := ai.GenerateObject(ctx, ai.GenerateObjectOptions{
    Model:      model,
    Prompt:     "Generate a recipe",
    Schema:     recipeSchema,
    MaxRetries: 5,
})
```

**After:**

```go skip-compile
retries := 5
result, err := ai.GenerateObject(ctx, ai.GenerateObjectOptions{
    Model:      model,
    Prompt:     "Generate a recipe",
    Schema:     recipeSchema,
    MaxRetries: &retries,
})
```

If you set `MaxRetries: 0` to get the default, remove the field instead.

### Telemetry: RecordInputs and RecordOutputs are pointers, and unset now records

**Impact:** compile error if you set `RecordInputs` or `RecordOutputs` as a
plain bool. **Behavior change:** a `telemetry.Options` (or the deprecated
`telemetry.Settings`) value that leaves them unset now records inputs and
outputs.

`telemetry.Options.RecordInputs` and `RecordOutputs` changed from `bool` to
`*bool`, the same way `MaxRetries` did. nil means record, as an omitted
`recordInputs` / `recordOutputs` does in TS; only an explicit `false` turns
recording off. `DefaultSettings()`, `WithRecordInputs(bool)` and
`WithRecordOutputs(bool)` keep their signatures and set the pointer. Read the
effective value with `ShouldRecordInputs()` / `ShouldRecordOutputs()`.

**Privacy:** in v0.5 a hand-built `telemetry.Options{}` recorded nothing. In
v0.6 the same literal records prompts, messages, tool arguments, generated
text, objects and tool results in your spans. If your spans must not contain
prompts or outputs, set both fields to `false` explicitly.

**Before:**

```go skip-compile
tel := &telemetry.Options{
    IsEnabled:     telemetry.Bool(true),
    RecordInputs:  false,
    RecordOutputs: true,
}
```

**After:**

```go
tel := &telemetry.Options{
    IsEnabled:     telemetry.Bool(true),
    RecordInputs:  telemetry.Bool(false), // keep prompts out of spans
    RecordOutputs: telemetry.Bool(true),  // or leave unset: nil records
}
```

### Evaluate end-event struct literals use the Decide field names

**Impact:** compile error only if you build these event structs yourself
(for example in tests); the SDK normally creates them.

`experimental_evaluate` is now `experimental_decide`, as in TS. The old type
names stay as deprecated aliases, so their embedded field is now named after
the new type. Reading promoted fields still compiles.

| Type | Embedded field to use in a struct literal |
| --- | --- |
| `telemetry.EvaluateEndEvent` | `DecideStartEvent` |
| `telemetry.EvaluationModelCallEndEvent` | `DecisionModelCallStartEvent` |
| `ai.EvaluateOnEndEvent` | `DecideOnStartEvent` |

### Unkeyed acp.TextContentBlock literals

`acp.TextContentBlock` is now an alias of `acp.ContentBlock`, which also carries
image blocks (`Data`, `MimeType`). Unkeyed literals such as
`acp.TextContentBlock{"text", "hello"}` no longer compile. Use keyed fields:

```go
block := acp.TextContentBlock{Type: "text", Text: "hello"}
```

## Behavior changes that can need an edit

- **`MaxTokens` below 1 is rejected.** As TS
  `prepareLanguageModelCallOptions`, `GenerateText`, `StreamText`,
  `GenerateObject`, `StreamObject`, batch text requests, `PrepareStep`
  overrides and the legacy `ToolLoopAgent` fail with
  `*errors.InvalidArgumentError` ("maxOutputTokens must be >= 1") when
  `MaxTokens` is 0 or negative. v0.5 sent the value to the provider. Leave
  `MaxTokens` nil for the provider default:

  ```go
  // v0.5: MaxTokens: &zero was sent as max_tokens: 0
  // v0.6: leave it nil, or set a value of at least 1
  maxTokens := 1024
  opts := ai.GenerateTextOptions{MaxTokens: &maxTokens}
  _ = opts
  ```
- **The legacy `ToolLoopAgent` rejects a negative `MaxRetries`.** A negative
  `MaxRetries` (on the agent or from `PrepareCall`) now fails the run with
  `*errors.InvalidArgumentError` ("maxRetries must be >= 0") before the
  model call, as TS `prepareRetries`. v0.5 silently made no retries. Use 0
  to disable retries.
- **Code mode has a default 10 s CPU limit.** `ExecutionPolicy.CPUTimeoutMs`
  (default 10_000) stops guest JavaScript that runs longer than that in one
  invocation with `*codemode.CPUTimeoutError`. Time in host tools does not
  count. Raise `CPUTimeoutMs` (and `TimeoutMs`) for long-running scripts.
- **Code mode caps concurrent scripts.** Like the TypeScript SDK, code mode
  now runs at most floor(available memory / (`ExecutionPolicy.MemoryLimitBytes`
  + 48 MiB)) sandbox invocations at once, at least 1 and at most 32. v0.5 had
  no limit. A script started over the limit fails right away with
  `*codemode.ConcurrencyError` ("Code mode maxWorkers limit reached (N).").
  Raise the limit with `codemode.SetMaxWorkers(n)`, or pass 0 to keep v0.5's
  unlimited behavior. `codemode.ResetMaxWorkers()` restores the default.
- **wazero is v1.12.0.** It was v1.9.0. Code mode's sandbox behaves the
  same: each invocation still gets its own QuickJS instance, memory and host
  bindings. QuickJS is now compiled once per process into one shared wazero
  runtime, so sandbox startup is faster than in v0.5 (about 2.4 ms instead of
  4.3 ms per trivial run on an Apple M1). If you pin wazero yourself, move it
  to v1.12.0.
- **MCP OAuth rejects unbound pre-registered confidential credentials.** Client
  information with a client secret (or a custom authenticator) but no
  `Issuer` and no stored authorization
  server information now fails `mcp.Auth` with an authorization-server mismatch
  error. Set `Issuer` to the authorization server the secret was registered
  with, or return it from `OAuthAuthorizationServerInformationStore`.
  Dynamically registered clients keep working.
- **OpenAI Responses `promptCacheOptions` is validated.** Only `mode`
  (`implicit` or `explicit`), `ttl` (`30m` or `12h`) and `prewarm` are sent.
  Invalid values such as `ttl: "24h"` fail before the request with
  `InvalidArgumentError`, and unknown keys are dropped.
- **`ToolChoice: none` is enforced.** A tool call under tool choice `none`
  now fails the call with `*ai.ToolChoiceViolationError` (check it with
  `ai.IsToolChoiceViolationError`) instead of running the tool. Any tool-choice
  violation ends the step with finish reason `error`.
- **`StreamText` keeps the request body only when asked.** As in TS
  (`include.requestBody` defaults to false), the step request, the
  `start-step` chunk and `Request()` no longer carry the provider's request
  body unless `Include: &ai.IncludeOptions{RequestBody: true}` is set, the
  same default `GenerateText` already had. The `GenerateText` step-end
  event's request and response bodies follow `Include` the same way.
- **Truncated streams finish with `interrupted`.** A provider stream that ends
  before its finish event reports `types.FinishReasonInterrupted` instead of
  `FinishReasonOther`, and the step runs no tools. Check for
  `FinishReasonInterrupted` if you detect truncated streams by the finish
  reason.
- **Prompt validation matches TS.** `GenerateText`, `StreamText`,
  `GenerateObject`, `StreamObject`, batch text requests and the agent calls
  return
  `*errors.InvalidPromptError` when neither or both of `Prompt` and
  `Messages` are set, or when `Messages` is an empty non-nil slice. Pass
  exactly one of them.
- **GenerateObject / StreamObject reject system messages in `Messages`**
  unless `AllowSystemMessages` is set, as `GenerateText` already did. Put the
  system prompt in `Instructions` (or `System`).
- **ACP lifecycle state persisted by v0.5.x does not resume.** As in TS, the
  persisted identity is now `agentIdentity`, so old state fails validation
  with "agentIdentity must be a string" (Cursor, GitHub Copilot, Grok Build
  and fx adapters). Start fresh ACP sessions after upgrading.
- **fx has an opt-in libfx runtime.** `fx.CreateFx()` without a `Runtime`
  behaves as in v0.5.x: the sandbox `fx acp` adapter, the v0.5.x
  `fx.BuiltinTools`, and v0.5.x lifecycle state. To move to the TS
  `@ai-sdk/harness-fx` runtime, set `fx.Settings{Runtime: fx.RuntimeLibfx}`.
  That runtime has other built-in tools (`fx.LibfxBuiltinTools`: `read`,
  `write`, `edit`, `bash`, `grep`, `glob`, `ls`, `askUserQuestions`), so
  update any `BuiltinToolFiltering` lists and tool-name checks. Its model
  requests leave from the host process, not the sandbox. It authenticates
  with AI Gateway or, as in TS, a codex or grok subscription found on the
  host (`~/.fx`, `$CODEX_HOME` or the OS keyring, `$GROK_HOME`), and it
  connects HTTP and SSE `MCPServers` from the host; command (stdio) MCP
  servers are not supported on it. The first session downloads the pinned
  `fx-core.wasm` (about 2.6 MB) into `os.UserCacheDir()/go-ai/fx/`; on a
  host without network access, pre-seed that cache or set
  `fx.WasmSource.Path`, then set `GO_AI_FX_OFFLINE=1`. Sessions do not move between
  runtimes. A v0.5.x sandbox-ACP session resumed under `RuntimeLibfx`, or a
  libfx session resumed under the default runtime, returns
  `*fx.IncompatibleStateError`. Finish or drop open sessions before you
  switch. As in TS, libfx state files are accepted for libfx 0.0.13 and
  0.0.14; any other version, or a file that fails the schema, fails with
  "Cannot resume fx: the saved state is invalid or incompatible." An open
  turn suspended by a TS host cannot be continued by a Go host, or the
  other way round, because each host computes its own settings signature.
  Finished turns resume on either host.
- **Wrapper providers no longer fall back to `OPENAI_API_KEY`.** Baseten,
  Cerebras, DeepInfra, Fireworks, Together, Vercel, Vertex MaaS and the Azure
  delegates read only their own API key environment variable, and Azure
  DeepSeek no longer falls back to `DEEPSEEK_API_KEY`. A missing key fails
  with `LoadAPIKeyError`. Set the provider's own variable (for example
  `FIREWORKS_API_KEY`, `TOGETHER_API_KEY`, `CEREBRAS_API_KEY`) or pass
  `APIKey`.
- **Failed generated-media downloads in BFL, Luma and fal return
  `*providererrors.ProviderError`.** As in TS, a non-2xx response when the
  provider fetches the generated image or audio is a provider error whose
  message is the HTTP status text, returned unwrapped. Match it with
  `errors.As` on `*providererrors.ProviderError` and its `StatusCode` instead
  of `*providererrors.DownloadError`.
- **KlingAI `VideoModel()` accepts any model ID.** As in TS, an unknown or
  empty ID is reported by `DoStart` (and so `GenerateVideo`) as
  `*providererrors.NoSuchModelError`, not by `VideoModel()`. Check the error
  from the call instead of only the one from `VideoModel()`.
- **A failed harness stop-condition suspension fails the turn.** When a
  `StopWhen` condition is met inside an `Agent` or `AgentSession` and the
  adapter's `DoSuspendTurn` returns an error (including
  `CapabilityUnsupportedError` from an adapter that cannot suspend), the turn
  now fails with that error, as in TS. v0.5.x finished the turn instead, so
  the error went unseen. If you use `StopWhen` with an adapter that cannot
  suspend, handle the error from the turn, or leave out the stop condition.
- **An OPA HTTP policy response without `result` is not-applicable, not
  denied**, as in TS. OPA answers an undefined decision (no rule matched) with
  `{}`; v0.5.x treated that as a deny. A tool call that no rule decides now
  falls through to the other approval rules. Policies that relied on "no match
  means deny" must return an explicit deny (for example a Rego `default`
  rule).
- **Telemetry span attributes from `EnrichSpan` and runtime context follow
  TS.** An `EnrichSpan` value that is an object, a struct, `nil` or a
  mixed-type array is now dropped; v0.5 wrote it as a JSON string attribute.
  A `[]interface{}` of one primitive type becomes a typed slice attribute,
  and Go's other integer and float kinds stay numbers. A runtime context
  value that is an object (any string-keyed map, a struct or a pointer to
  one) is flattened into `ai.settings.context.<path>` attributes instead of
  one JSON string. If a dashboard or query reads those JSON strings, read the
  flattened keys, or return primitives from `EnrichSpan`.
- **Perplexity embedding provider options are validated.** As in TS, a
  `dimensions` that is not a positive integer, or an `encodingFormat` other
  than `base64_int8` or `base64_binary`, now fails `DoEmbed`/`DoEmbedMany`
  with `*providererrors.InvalidArgumentError`. v0.5 truncated a fractional
  `dimensions` and ignored or sent other values. Pass a positive integer and
  a supported format.
- **A legacy `ToolLoopAgent` step timeout is `context.DeadlineExceeded`.**
  The per-step deadline (`Timeout.PerStep`, or a `PrepareCall` `Timeout`
  override, which now applies as in TS) reaches the model call as a
  deadline. A timed-out step fails with an error wrapping
  `context.DeadlineExceeded`; v0.5 surfaced `context.Canceled`. Update
  timeout checks:

  ```go
  // v0.5
  if errors.Is(err, context.Canceled) { /* step timed out */ }
  // v0.6
  if errors.Is(err, context.DeadlineExceeded) { /* step timed out */ }
  ```
- **The legacy `ToolLoopAgent` step timeout now covers tool execution.**
  In v0.5 the per-step deadline (`Timeout.PerStep`) ended when the model
  call returned, so a tool could keep running past it. As in TS, the step
  timeout now also bounds the step's tools: a tool that used to finish
  after the step deadline is cancelled (its ctx is done), and the run ends
  with `context.DeadlineExceeded` before the next step, even if the tool
  ignored the cancellation. Size `Timeout.PerStep` for the model call plus
  its tools, or use `Timeout.Total` or a timeout inside the tool instead.
- **The `WorkflowAgent` root span is `ai.workflowAgent.stream` for
  `Generate` too.** TS uses that operation ID for both methods; v0.5 named
  the generate root `ai.workflowAgent.generate`. The root now opens after
  the approved tools from the message history ran, so those resumed tool
  calls get no tool span, as in TS. Update queries that match
  `ai.workflowAgent.generate`.
- **UI message streams fail on an out-of-sequence chunk.** When
  `CreateUIMessageStreamWithOptions` or `ToUIMessageStream` has an `OnEnd` or
  `OnStepEnd` callback, a chunk the message state cannot apply (a
  `text-delta` without its `text-start`, a tool result for an unknown tool
  call) now ends the stream: the error channel carries a
  `*ai.UIMessageStreamError`, later chunks are not delivered, and `OnEnd`
  reports a failed outcome with that error. v0.5 passed the error to
  `OnError` and kept streaming. Without those callbacks the chunks are not
  checked, and `OnError` is no longer called for them. Emit each part's start
  chunk before its deltas, or check the error channel with
  `errors.As(err, &uiErr)` where `uiErr` is a `*ai.UIMessageStreamError`.
- **An empty `Telemetry.Integrations` slice turns telemetry off for the
  call.** As in TS, a non-nil `Integrations` replaces the globally
  registered integrations, so `[]telemetry.TelemetryIntegration{}` now means
  none: no spans or events for that call. v0.5 fell back to the global
  integrations for an empty slice. Leave the field nil to use the globals:

  ```go
  // v0.5: an empty slice used the global integrations
  tel := &telemetry.Options{Integrations: []telemetry.TelemetryIntegration{}}
  // v0.6: leave it nil for the global integrations
  tel = &telemetry.Options{}
  _ = tel
  ```
- **Telemetry spans come from the `ai` and `gen_ai` tracers.** As in TS,
  `LegacyOpenTelemetry` without a `Tracer` uses `otel.Tracer("ai")` and the
  GenAI `OpenTelemetry` integration `otel.Tracer("gen_ai")`. v0.5 used
  `"ai-sdk"` for root spans and `"go-ai"` for child spans. Every span of a
  call now comes from the root's tracer, including a `Tracer` you pass.
  Update filters on the instrumentation scope name:

  ```go
  // v0.5: spans had the instrumentation scope "ai-sdk" or "go-ai"
  // v0.6: "ai" (legacy) or "gen_ai" (GenAI), or your own tracer's name
  legacyScope, genAIScope := telemetry.LegacyTracerName, telemetry.GenAITracerName
  _, _ = legacyScope, genAIScope
  ```
- **Tool approval and tool-context errors fail the call.** A tool context
  that fails the tool's `ContextSchema`, an approval function whose context
  fails it, an unknown approval status and an unsupported `ToolApproval`
  value now end `GenerateText` with an error (and error `StreamText`'s stream
  and the agents' runs), as in TS. v0.5 turned them into tool-error results
  the model saw. A tool's own `Execute` error is still a tool error:

  ```go
  // v0.5: the call succeeded; result.ToolResults[0].Error held the error
  // v0.6: the call fails with it
  var validationErr *providererrors.ValidationError
  _ = errors.As(err, &validationErr) // validationErr.Context.Field == "tool context"
  ```
